# 三人团队分工与验收

以下是建议分工，不是已经完成的功能清单。三人先共同维护一个可验证的主链，不为每个 Agent 单独复制整套后端。

## 职责边界

| 成员 | 主责 | 主要交付 | 复核 |
|---|---|---|---|
| A 平台和模型 | Provider 适配 任务编排 持久化 预算 | 统一模型接口 项目版本 任务 API 账本 | B 复核执行及预算边界 |
| B FPGA 和验证 | 模块契约 RTL EDA 约束 独立 TB | 版本化端口 验证用例 波形与综合证据 | A 复核集成 C 复核需求对应 |
| C 交互和集成 | 需求问答 前端 工件展示 演示 | 需求确认页 进度与状态 报告下载 | A 复核接口 B 复核验证标签 |

报价和硬件选型先作为后续独立插件，由明确的数据源驱动；不要挤占第一阶段闭环验证的时间。

## 开发约定

1. 仓库所有者添加两名协作者；每人独立账号，不共享 PAT 或 API Key。成员用户名尚未提供，本轮未配置 CODEOWNERS、成员权限或分支保护。
2. `feature/provider-api`、`feature/verification`、`feature/requirements-ui` 等是建议分支名，实际创建前从最新 main 切出。每个 PR 明确影响范围，由另一人审查。
3. 运行代码、测试、配置和规范一起审查；格式检查、类型检查和验证失败不能由模型总结为通过。
4. 原始冻结文件修改需建立新版本和来源关系；不直接更新历史成绩、旧 hash 或旧来源提交声明。
5. 有行为改动先加失败测试，修复后运行完整受影响测试。不能只测成功路径；网络失败、取消、断电式中断和无有效代码都要建模。

## 首先冻结的接口

- **需求记录**：需求 ID、版本、用户确认项、未决项、变更原因和验收条件；不能把模型自行猜测写成已确认。
- **模块规格**：端口、位宽、时钟、复位、吞吐、延迟、数值范围及异常行为。
- **项目配置**：目标器件、开发板修订、EDA 版本、约束来源和运行预算。未知板卡引脚禁止补造。
- **任务和工件**：project_id、requirement_version、interface_version、job_id、内容 hash、生成模型、状态、验证证据和失效原因。
- **上位机协议**：寄存器或帧格式、单位、端序、版本号、错误码、状态机、超时及重连策略。协议契约驱动 FPGA 与主机两边，不让两边各自猜测。

上述是建议字段，不是仓库已存在的 Schema。应由 A 和 B 先共同定稿，C 再按稳定 API 开发页面。

## 首版验收门

| 阶段 | 可展示证据 | 不能替代的内容 |
|---|---|---|
| 需求已确认 | 用户确认记录和规格版本 | Prompt 改写不等于需求确认 |
| 候选已生成 | RTL 文件 hash 和模型调用记录 | 非空代码不等于正确 |
| 内部检查通过 | 编译和有限检查日志 | 不等于独立功能通过 |
| 独立功能通过 | 冻结 TB 版本 波形 断言结果 | 不等于时序收敛或上板成功 |
| 综合实现通过 | 器件 约束 DRC 资源与时序报告 | 不等于电气和产品测试完成 |
| 上板验收完成 | 板卡版本 仪器和场景记录 | 不能用软件模拟状态代替 |

评测侧独立 TB 不交给生成侧；用于调试的公开 TB 可以输入，但不再作为独立验收证据。所有状态均允许 NOT_RUN、FAIL、UNKNOWN 和 INDETERMINATE。

## 需求变更处理

用户追加需求后新建变更记录，而不是直接覆盖所有提示词。比较受影响的接口、RTL、TB、约束和上位机协议；改变接口时提升接口版本，使下游旧工件失效。限定受影响分支重做并回归，不相关已通过工件可按依赖关系复用。最终演示必须展示版本关系和证据，而非拼接不同版本的“通过”截图。

编码规范先落为可检查规则和示例，再把流程整理为 Skills。RTL lint、CDC/复位检查、接口校验、独立 TB 和必要的时序分析才是执行门；Skills 不能代替这些检查。
