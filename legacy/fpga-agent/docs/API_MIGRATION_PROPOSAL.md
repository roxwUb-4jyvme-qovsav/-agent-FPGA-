# API 模型迁移实施建议

状态：审查建议，尚未实施；服务商、模型账号和预算待确认。旧模式全部保留，不以新实现冒用原模型、来源锁和历史成绩。

## 方案比较

| 方案 | 优点 | 风险及判断 |
|---|---|---|
| 只改 URL 和 Key | 表面改动少 | 被本地 URL、tokenize、usage 和 GPU 准入阻断，不可直接采用 |
| 保留本地模式 新增 API Provider 和新版 Runner | 能逐步复用检查器并做回归 | 需要拆分调用和准入策略，推荐 |
| 从零重写整个编程 Agent | 无历史耦合 | 重复丢失现有证据、诊断和预算机制，三人团队不宜优先 |

## 建议边界

```text
需求确认和项目版本
        ↓
标准化模块规格和接口契约
        ↓
新版 Coding Runner ── ModelProvider ── 远程 HTTPS API
        ↓
候选处理及接口检查 → 受限 EDA Worker → 公开诊断反馈
        ↓
独立验证服务 → 带证据的项目工件
```

旧 `run.sh`、Baseline、冻结 Skill 和历史本地模式作为对照保留。不要用 monkey patch 替换全局模型函数来接入远端；多人并发时会造成 Provider、usage 或任务串线。通过显式依赖参数注入 Provider 与项目配置，新增 Runner 版本。

建议新增 `app/providers/`、`app/coding/`、`app/projects/` 和 `app/workers/`，这些目录当前尚不存在。先有接口契约再分工，不要求先引入大型编排框架。现有检查器的直接复用仍需处理器件、顶层、全局审计状态及工作目录假设，不能以一个通用函数签名掩盖旧耦合。

## Provider 契约

输入包含 model_id、公开规格、版本化指导、最大输出预算、绝对截止时间及 request_id。Provider 返回下列信息；字段必须是普通数据，不是由模型自行声明的“可信结果”。

| 字段 | 要求 |
|---|---|
| `text` | 仅供候选提取的代码文本，空值显式失败 |
| `status` | completed incomplete refused failed cancelled unknown 等确定状态 |
| `requested_model` 与 `actual_model` | 保留实际服务端身份，按显式允许的别名或快照策略验证 |
| `usage` | 真实输入输出及服务商细项，保留原始字段用于审计 |
| `usage_complete` | 缺失或中断不能伪造成零消耗 |
| `preflight_count_kind` | exact estimated unavailable 区分，不能伪造本地 tokenizer |
| `provider_request_id` | 追查服务端请求，不能包含密钥 |
| `latency_ms` 和 `error_code` | 区分网络、限流、鉴权、配额、格式与内容失败 |

账本的 token 数以服务商真实 usage 为准；缓存 token、推理 token 等可能是输入输出总数的子项，不能再无条件加一次。单价表必须有币种、计价单位、生效日期和来源；金额使用定点 Decimal，usage 不完整时金额标记估算或未知。

每次调用前预留输出预算并检查上下文余量；每次调用后记实际消耗。超时后服务商可能已经执行或计费，应记录未知消耗并保守预留，不把预算回补到满额。模型和 EDA 共用绝对截止时间，不能每轮重置任务总时限。

## 远程模式部署

- API Key 只存在业务后端或 Worker 的环境密钥管理中，不在仓库、Prompt、浏览器或普通日志中。
- Provider 只访问批准的 HTTPS 目的地址；禁用非预期重定向，限制响应大小、超时和并发，错误信息脱敏。
- 远程模式的健康检查分别报告 Provider 配置、服务能力和 EDA 可用性；不要求本地推理显卡，也不每次健康轮询都做付费生成。
- 模型输入限于用户授权的公开规格和允许反馈。独立评测隐藏资产不送给模型；真实产品代码发送外部服务前应遵循团队的数据要求。
- 生成代码在受控工作目录运行，无主机密钥和任意 shell 权限；模型不能自行决定安装软件、刷写硬件或更改电压。
- 429 和暂时性故障可以在总 deadline 内有限退避，但不得无界重试；结果不明确的生成、任务提交或硬件操作不自动重新执行。
- 新配置使用 `provider`、`model`、`api_protocol` 和 API Key 的环境变量名；不要把真实 Key 作为 JSON 配置字段提交。

## 分阶段任务和验收

1. **配置和适配层**：明确协议、完成状态、容量策略和 usage 映射，契约测试覆盖正常文本、拒绝、截断、空文本、非 JSON、401、429、5xx、超时、缺失 usage。只用 MOCK 时清楚标记，不能宣称真实 API 通过。
2. **单模块 Runner**：保留候选安全检查、接口校验、修复上限及账本。支持取消和结果未知状态。以接口方式接检查器，不改旧模型限制。
3. **真实连通测试**：使用团队开发 Key，先一次小任务，记录请求 ID、响应模型、usage、延迟和费用状态。测试前约定最大消费，不跑无界压力测试。
4. **独立 RTL 验证**：由 B 编写并冻结独立 TB，覆盖计数器溢出、FIFO 满空及复位等边界；生成侧拿不到验收答案。内部调试可使用公开开发 TB，须与保留测试分开。
5. **修复闭环**：注入可定位编译错误和公开功能错误，确认反馈后修复，无法修复则失败或不确定；禁止为了通过删除断言。
6. **团队集成**：需求版本、接口版本、源码 hash、Provider 配置和 EDA 结果可关联；变更需求使受影响工件失效，并触发限定范围的重新生成与回归。

选主模型前，准备同一套独立开发任务，以相同任务约束比较首次编译率、独立功能通过率、最多若干轮修复后的通过率、综合资源、耗时和实际费用。分别列出公平预算对比与最佳可用配置对比，不混成一个成绩。

## 不纳入第一阶段

全自动 PCB 交付、任意 FPGA 厂商工具链、所有原理图 CAD、通用形式证明、多人公网生产服务和自动采购付款。可先规划适配接口，不应为比赛原型提前实现所有功能。
