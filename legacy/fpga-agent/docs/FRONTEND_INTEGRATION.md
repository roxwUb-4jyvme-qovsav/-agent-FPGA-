# 前端与业务后端接入指南

## 推荐拓扑

浏览器 → 队员自己的业务后端 → Agent HTTP 服务 → 本地模型与 Vivado。

本仓库尚无前端。现有服务绑定 `127.0.0.1:7860`，模型在 `127.0.0.1:8002/v1`；这是部署配置，不是任意客户端可访问的固定公网地址。前端不要直接访问模型端口。服务未提供面向浏览器的 CORS 和用户账户体系，推荐由同源业务后端代理。业务后端只允许预设的服务地址，避免任意 URL 代理。

鉴权头为 `Authorization: Bearer <部署方私下配置的令牌>`。令牌保留在业务后端环境中，不写入前端构建变量、浏览器存储、代码、截图或日志。开发环境单独配令牌，勿复用赛事凭据或调用比赛实例。

## 健康检查

`GET /v1/health`，成功返回 200，检查 `ready=true`、`track="rtl"`、`model` 和 `context_tokens`。未鉴权返回 401；未就绪可能返回 503。不要仅看端口能连上。

## 提交任务

`POST /v1/solve`，请求头还需 `Content-Type: application/json`。以下只是公开请求格式示例，本次上传没有发送请求。

```json
{
  "task_id": "dev-example-001",
  "nonce": "由业务后端为本次任务生成的唯一随机串",
  "mode": "agent",
  "prompt": "完整公开 RTL 规格，包含模块名、端口方向和位宽，以及功能定义",
  "interface": "",
  "deadline_s": 900
}
```

`task_id`、`prompt` 必须是非空字符串。`mode` 为 `agent` 或 `baseline`；后者会实际调用裸模型，不是模拟开关。`interface` 可为空，规格应包含完整接口。`deadline_s` 接口接受有限数值 5～3600；比赛协议为 900，而内部 Agent 仍有原来的 300 秒任务预算，不能在前端宣称加大 deadline 就扩充内部预算。不要为生成请求上传文件路径、独立 TB、隐藏答案或参考 RTL。

成功立即返回 202：

```json
{"job_id":"服务分配的任务编号","task_id":"dev-example-001","status":"queued"}
```

同一非空 nonce 再次提交会返回原任务，不更新原输入或重新求解。POST 超时后不要换 nonce 自动重发，这可能重复消耗模型。业务后端应持久保存 nonce、task_id、job_id；当前服务没有按 nonce 查询任务的独立接口，提交结果不明确时应标记未知并排查。

## 查询与展示

每约 2 秒 `GET /v1/jobs/<job_id>`，携带相同鉴权头。`queued` 为排队，`running` 为处理中，`done` 才有最终内容。等待页面可以取消轮询，但服务没有公开的任务取消接口，关闭页面不会取消已提交任务。

最终响应包含 `solution`、`trace`、`elapsed_s`，并可能包含 `request_status`、`execution_result`、`known_usage`、`trace_incomplete`。这些字段必须分别展示：

|情况|建议界面状态|
|---|---|
|HTTP 202|已接收，等待执行|
|queued/running|排队/执行中|
|done 且 solution 为空|未得到有效最终 RTL，不显示“通过”|
|done 且有代码|候选已生成，尚需依据验证记录判定|
|SYNTH_PASS_FUNCTION_UNPROVEN|内部综合通过、功能未被独立证明|
|INDETERMINATE|无法判断，不能画成绿色功能通过|
|trace_incomplete=true|证据不完整，明确提示|

`trace` 是 JSONL 字符串，逐行解析并容忍未知工具事件；原始文本保留下载入口。代码、日志、错误信息以纯文本展示，不用未经转义的 HTML 插入，避免日志内容触发脚本。界面不要凭 rc=0、非空 RTL 或 HTTP 200 合成 L2/L3 标签。独立 L1/L2/L3 不由此 HTTP 接口自动提供；需要另建隔离评测服务，不能把评测资产传给模型。

## 常见错误与并发

- 400：请求字段不合法，修正后由用户明确提交。
- 401：鉴权失败，检查业务后端配置，不向页面返回令牌。
- 404：job_id 不存在或服务已重启，保留原记录，不自动重发。
- 503：未就绪、准入故障或容量已满，停止新任务，不循环重投。
- 超时、断连、响应格式异常：标记结果未知/失败，保存已知 job_id 继续调查，禁止自动创建新任务掩盖首次失败。

当前内核串行求解，最多保留 4096 项任务身份、4 项未完成请求和受限结果内存。队内多用户的排队、权限、额度与持久化应由业务后端实现；不要把它当作无限吞吐的多租户平台。源码依据：serve/submission.py 的 validate、Jobs.submit/get/_work 和 Handler，以及 serve/serve_api.py。
