# FPGA 协同开发平台实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 在用户指定的 fpga_platform 目录实现可运行的本机工程工作台，按已有规格追踪完整首版要求及实际验证状态。

**Architecture:** FastAPI 模块化单体提供同源 API，PostgreSQL 保存业务事实，文件工件按内容哈希原子落盘。React TypeScript 工作台调用 API；独立 Worker、产品协议库和保留验证服务分离。外部工具与付费调用在条件未登记时明确阻断。

**Tech Stack:** Python 3.12、FastAPI、SQLAlchemy 2、Alembic、PostgreSQL、React、TypeScript、Vite、pytest；前端选型为实施决定。

**Spec:** [开发规格书](../../reference/development-spec/FPGA多Agent协同开发平台开发规格书_v1.0.md)；[总体设计](../../reference/overall-design/FPGA多Agent协同开发平台完整设计方案.md)。

## Global Constraints

- 所有源码与开发配置位于 fpga_platform，来源文档和历史快照只读。
- packages/contracts 保存原版 70 个 Schema；API 前缀 /api/v1，schema_version 为 1.0，设备 capture/1.0。
- 可读性优先，小模块、类型标注；状态机、事务、权限、时序、算法关键处使用中文注释。
- 默认绑定 127.0.0.1；会话 HttpOnly、SameSite Strict，写操作 CSRF；项目 ACL 与 global_role 分离。
- ETag、If-Match、Idempotency-Key、不可变工件、审计、队列租约与 fencing token 均不得用前端演示替代。
- 模型真实预算默认 0；无隔离环境不得执行生成代码；未配置工具不得输出 PASS。
- PostgreSQL 是部署数据库，SQLite 只允许显式测试或本地开发模式，不声明满足 PostgreSQL 并发验收。
- 84 项 P0 验收计划独立跟踪，未执行为 NOT_RUN；不能将单元测试等同完整首版验收。
- 8/16 通道、100 MHz、divider 10/100、深度 16–4096 的 2 次幂、UART 115200 8N1、CRC16 CCITT FALSE。
- 不自动推送、发布、采购、烧录或调用真实付费服务。

## Review Focus

- 跨项目资源 ID、越权角色、过期会话与 CSRF 必须由后端拒绝。
- 相同幂等键不同请求、过期 ETag、晚到 Worker 结果不可覆盖新事实。
- 错帧、CRC 损坏、触发通道 15、掩码和 ABORT 同拍不能产生假采集结果。
- 重启、取消、预算未知消费、依赖循环和失效证据不能变为成功。
- 工具缺失、Provider 未配置、外部权限未批准须显示真实阻断原因。

## 文件与接口边界

- apps/api：config.py、database.py、models.py、security.py、errors.py、services/、routers/、main.py、cli.py。
- apps/web：React 工作台、类型化客户端、管理编辑与设备波形。
- packages/contracts：schemas/、api/、examples/、protocol/、validation.py，原始文件附 source-lock.json。
- packages/orchestration：dag.py、state.py、snapshots.py；packages/model_gateway：provider.py、budget.py。
- packages/knowledge：index.py、parsing.py；packages/tool_gateway：policy.py、extensions.py；packages/quotes：pricing.py。
- products/analyzer：protocol.py、capture.py、export.py、rtl/；acceptance_service：signing.py、verification.py。
- workers：工具环境检测、受限模板和主动领取客户端；脚本 scripts/；文档 docs/。
- 主服务领域模块使用 Python 字典和 dataclass 接口，不直接依赖数据库；HTTP 持久化由 apps/api 负责。
- 产品库统一接口：Frame、encode_frame、decode_frame、FrameDecoder；CaptureConfig、CaptureEngine；方法细节在实现报告中冻结。
- 数据响应遵循随附 OpenAPI 的资源包装；前端不得创造隐式演示 API。必要的初始化与开发诊断扩展使用 /api/v1/setup 和 /api/v1/system 前缀并记录。
